## Reliability findings and corrections

Pause: storage already awaited the IndexedDB transaction before changing the committed React model. The reported click→immediate reload could precede a queued commit; it was not proof that an acknowledged committed PAUSED record became ACTIVE. Save-status code also marked each completed operation Saved even when later writes remained, and swallowed errors before success continuations. V2.1 adds small synchronous ordered intents for lifecycle, drafts, Done/Undo and weight-unit choice before asynchronous commit. IDB mutation receipts make replay exactly once, including a crash after commit but before removing the intent. Pending data is replayed before the UI opens, with dataset/session identity checks; incompatible/corrupt intents enter recovery instead of silently resuming or replacing data. Invalid user entries are validated before creating a record intent, so a blank Done does not poison recovery. Success appears only after commit; pending counts, errors and navigation warnings remain honest. Lifecycle controls guard double submissions. Pause duration ends at action time, independent of performed seconds.

Import: the old flow correctly rejected an export that became stale after a Finish/change, but the error was in the page behind the modal. Baseline tests directly reproduced this guard without modifying valid records. Restore and rollback also bypassed the ordinary mutation queue. V2.1 previews replacement versus merge semantics, counts sessions/recorded sets, distinguishes no-change/cancel/errors, serializes replacement, and downloads a fresh current backup before a changing restore. Existing atomic active/previous workspace pointers and validation guard remain intact. Failed writes cannot partially replace history. The previous workspace can be restored, with a fresh safety export. Invalid/future/checksum/Winter Strong files are not accepted as Everyday Athlete data.

Existing backup/dataset schema remains3; no new workout schema migration or destructive rewrite. The journal is a small separate, namespaced localStorage recovery buffer, not an alternate history database, and is absent from normal workout backups. Timed-set UI checkpoints use sessionStorage; only explicitly observed/manual seconds enter ordinary drafts. Existing lb/kg values, entered precision, optional weightUnit metadata and migration readers remain supported. Older V2 can read committed records but cannot replay pending V2.1 intents: recover/settle pending actions and export before any rollback. Storage APIs/device failure cannot be made immune to all browser/OS data eviction or power loss.

## Bounded usability changes

- Bottom tabs cancel the inherited global nav margin of18px, sit at bottom0 with opaque safe-area padding, and hide when an actual visual-viewport keyboard contraction is detected. Timer clears navigation and is hidden during set entry. Automated viewport and simulated keyboard checks are not physical iPhone certification.
- Rest timer opens/collapses Ready or Running without resetting. Mini/radial ring is neutral Ready, reflects actual remaining deadline while Running, green Done0:00 for approximately5 seconds, dismissible with X, then restores selected duration. X resets immediately, no Pause. Background expiry uses original deadline, never creates a delayed audio event; only in-foreground completion can issue one brief beep. Settings has Silent(default)/Short beep and limitations. Fixed a captured-event preference bug that reverted Short beep (and the same deferred control pattern for RIR/date). Remaining countdown is clamped to selected duration to prevent a stale render clock briefly showing6 seconds for a5-second setting.
- Each timed-set row has a foreground stopwatch. Start/Stop measures observed foreground ticks only, prefills editable Seconds, never marks Done, and requires stopping before Done. Pause, overlay, collapse, leaving Workout, background/pagehide or a long tick gap stops measurement; unobserved suspended time is excluded. Last observed seconds can recover from a same-tab interruption. Manual corrections remain authoritative, and a subsecond stop does not claim to have filled a value.
- Supersets are still manual, with one existing named group supporting2+ members. Visual grouping places members adjacently in original relative order, adds a subtle shared edge/group heading and visible Unlink, and provides Group exercises near the workout header. Original prescription/performance arrays/IDs are not reordered. Unlink restores normal order; users may log freely.
- Finished summary counts confirmed prescribed sets, extras, prescribed exercises with work, additional performed exercises, elapsed-workout duration, partial/modified status and recorded exercise highlights. No invented achievements or progression claims.
- Settings shows structurally verified release.json revision/schema/base when available; otherwise says release identity unavailable. It never claims an unknown candidate is the latest deployed version.
