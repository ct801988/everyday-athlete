# Security scope and compatibility limits

The Worker is a network access boundary for synthetic app code. Workout data, drafts, schedule, history and backups stay in the browser/device unless the user deliberately exports a file. Static hosting still exposes connection metadata (IP, hostname, timing and request paths) to Cloudflare. Provider operational/security metadata is outside application control. There is no claim of anonymous hosting, encryption of IndexedDB or individual family-user authorization.

The password is checked before every allowlisted asset and before unsupported paths/methods. Authorization and Cookie/Referer headers are removed before the internal ASSETS fetch. No user input is reflected into HTML. Invalid configuration and asset errors fail closed. Native Web Crypto verifies keyed credentials; the password never enters frontend code. Runtime-generated test secrets are held in memory, and a final scan found neither those secrets nor their Basic encodings in repository/payload files. No actual deployment password has been selected or stored.

Cache policy has two distinct purposes: shared HTTP/CDN caches must not expose protected files, while the authorized device deliberately stores a scoped offline shell in Cache Storage. The local warmed-cache/fresh-client test verifies no unauthenticated delivery in workerd. It cannot prove production CDN behavior. Browser-managed Basic credentials and offline cache can persist after leaving the page; there is no reliable logout or remote wipe. Password rotation is not revocation of an already downloaded copy. The device lock and an unshared browser profile remain necessary.

The hostname check, disabled version URLs, strict path allowlist, no redirects/fallbacks and Worker-first config reduce bypass opportunities. Live provider aliases and automatic endpoints must still be enumerated and tested after N04 approval. Query-string asset requests are intentionally rejected; the current app does not require them. No source maps or source/database endpoints are uploaded. CSP permits only same-origin scripts, styles, assets, manifests, workers and connections. Chromium workout, backup and controlled-update flows ran under this CSP without page errors; Safari behavior is not inferred from Chromium.

Local tests use real Cloudflare workerd and ASSETS handling via Wrangler, with an ephemeral loopback HTTPS certificate. Chromium trusts only that test certificate's public key for the test process; no system trust settings changed. It is not a public CA certificate test. No hosted Cloudflare stack, physical iPhone/Android, Add to Home Screen storage container, VoiceOver/TalkBack or provider account quota was tested. Native Supabase verification remains deferred, not waived, and none is required or included for this local-only preview.
