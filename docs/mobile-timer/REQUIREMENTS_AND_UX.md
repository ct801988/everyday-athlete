# Bounded workout UI and rest timer — implemented candidate

Authority: latest product-owner implementation authorization; Decision Register v0.8. This document replaces the timer implementation proposal's pending defaults. It does not approve training prescriptions or distribution.

The read-only Winter Strong V5.1 archive informed the dark compact header, restrained teal action color, white exercise cards, typography, touch-friendly numeric controls, clear set status and bottom navigation. Its source, media and program content were not modified or integrated. Everyday Athlete retains React, its own domain contracts, IndexedDB, synthetic fixtures and history. Foundation remains 3 sessions/week, Strength 4, Fit deferred. The exercise overlay now accepts a canonical fixture so the synthetic conditioning example cannot incorrectly open strength information.

The workout screen distinguishes program/session, demonstration exercise, prescription and editable draft values. Weight and repetitions remain fast numeric fields, Done is deliberate, corrections/Undo retain history, RIR is optional. Drafts/suggestions do not become performed records on navigation, timer actions, reload or expiry. Saved-set progress derives from confirmed actuals only. Device/recovery utilities remain available below the workout; bottom navigation is fixed and the timer remains mounted across tabs/overlays. Safe-area padding and content clearance permit scrolling controls above the dock. No synthetic media is represented as approved exercise instruction.

Timer state: Ready → manual Start → Running → atomic completion claim → Ready with a brief subtle green “Rest complete” indication. X/Stop & Reset clears the run and pending sound eligibility, restores the selected duration and collapses the options immediately, with no confirmation. No Pause/Resume or auto-start. Selecting a duration changes selection only. “Use selected as my default” explicitly saves the preference. Presets are 30/60/120/180 seconds; custom bounds 5–3600 inclusive, step 5. Options lock during Running until reset. Silent is default; Short beep requests one ~160ms sound, never a repeating alarm. Missing/unavailable sound does not block the timer.

Three concepts remain distinct: local preferred duration; current selected/run duration; prescribed workout recommendation. Synthetic sessions contain no approved prescribed rest value. That absence remains unknown, is not inferred from exercise names/actuals, and is explained in the options. The 120-second initial preference is a software default, not exercise-science guidance.

Countdown uses persisted wall-clock deadlines plus an active monotonic elapsed-time floor; no decrement-per-callback or ticking database writes. This handles throttled callbacks and ordinary interruptions. Moving the wall clock forward can expire early; changing the device clock across restart can change displayed remaining time. A new run ID prevents replay; transactional completion claims provide at-most-once sound across tabs. Audio eligibility exists only in the initiating active document after a user gesture and is cleared by hiding, reset, dataset activation or reload. Background/restored expiry is visual only. A crash between claim and playback may drop sound; avoiding duplicates takes priority. Safari/PWA/locked-screen audio is best-effort and unverified on physical hardware.

The compact dock measured 74 CSS pixels high at all four tested sizes; the prior inline all-controls section measured 274.8125px at 390px width. This is a ~73% reduction in collapsed footprint, exceeding the illustrative 20–25% target by moving secondary controls into a drawer; it is not a like-for-like reduction with all options expanded. Primary targets remain at least 44px. Dark normal digits, completion text as well as color, no animation, focus outlines, no per-tick live announcements, semantic labels and keyboard controls are supplied. Drawer content scrolls independently on small landscapes. Actual Safari keyboard, VoiceOver, Dynamic Type, safe-area and Add to Home Screen behavior still require owner verification.

Schema-1 local data normalizes to schema 2 in one IndexedDB transaction, adding the new dataset at a new key and switching the active pointer only after validation. Exact original dataset and its prior recovery pointer are retained. A future running legacy deadline is retained with a deterministic run identity; legacy paused/expired timers return Ready, 120 seconds and Silent. Existing actuals, unknown effort/RIR, prescriptions, drafts, audit, schedules and identities are preserved. The Backup screen can export the retained schema-1 dataset in the original v0.3.0 envelope for compatible code rollback. New exports include timer selection and preference independently. Legacy file checksum is verified before conversion and the staged normalized representation gets a new checksum; the original file is untouched. Restore preview discloses conversion. No silent merge is introduced. Unsupported versions fail closed.

No schema changes require a new object store, so IndexedDB version stays 2. Backup envelope formatVersion stays 1; dataset.schemaVersion distinguishes v1/v2, and appVersion identifies the writer. The strict old app refuses new schema-2 data; rollback requires a compatible backup/profile or forward repair, not just older JavaScript.
